# NAVIX — Visual & Functional Defect Audit

**Date:** October 14, 2026  
**Branch:** `demo/final-visual-experience`  
**Inspection Environment:** Real Next.js production & development sessions, live PostgreSQL 18/PostGIS (Port 5433), live FastAPI (Port 8000), real Chromium sessions.

---

## Screen-by-Screen Comprehensive Defect Inventory

| Page | Component | Observed Problem | Severity | Type | Fix Strategy |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Homepage** | Hero Section | Copy differs slightly from specification ("Find your route..." vs "Build a journey around where you want to go, how you want to travel, and what you want to spend."); Secondary CTA is "Explore destinations" instead of "Explore India". | High | Visual / Copy | Update hero copy exactly to user specification; align secondary CTA label and styling. |
| **Homepage** | Background Scenes | Background photography was confined to hero viewport; scrolling into Composer/Discover shifted immediately to plain beige background without sustained cinematic destination atmosphere. Only 5 scenes were configured instead of 6 (missing Rishikesh / Varanasi river scene). | Critical | Visual | Implement a persistent, layered `SceneBackground` system with 6 geographically verified scenes (Manali, Goa, Udaipur, Munnar, Jaipur, Rishikesh). Use `IntersectionObserver` with smooth crossfade (600–1000ms) and readable gradient overlay. |
| **Homepage** | Trip Composer | Sits in a heavy stacked card instead of a sleek, single-line horizontal composition on desktop. Border lines and padding feel too template-like. | High | Visual / Hierarchy | Re-architect Trip Composer into an ultra-clean, single-tier horizontal glass bar on desktop (`xl:flex-row`), clean stacked on mobile. |
| **Homepage** | Interactive Feedback | Buttons and destination cards lack tactile micro-interactions (no 1.02–1.04x subtle zoom, no button icon shift, flat hover states). | Medium | Visual / Interaction | Implement reusable motion tokens: `photo-card-hover` with 1.03 scale zoom, 2-4px icon shift on CTA hover, and smooth cubic-bezier transitions. |
| **Explore** | Catalog Grid | Cards use uniform rectangular grid without editorial rhythm or visual hierarchy. Feels like a database dump rather than a curated travel guide. | High | Visual / Hierarchy | Redesign explore catalog with mixed editorial cadence: featured hero card (2-col span), vertical cards, and compact discovery grid. |
| **Explore** | Image Provenance | Fallback images for destinations without custom photography defaulted to random or unverified assets. | High | Visual / Content | Replace all placeholder or unverified images with authenticated regional travel photos or intentional neutral fallback ("Photo unavailable" with warm sand surface). |
| **Destination Detail** (`/explore/[slug]`) | Hero & Overview | Stats (Daily budget, Best Season, Ideal Duration) were rendered inside multiple separate white card boxes, creating a "dashboard / SaaS card wall" aesthetic. | Critical | Visual / Hierarchy | Convert separate stats cards into an elegant inline contextual meta strip directly beneath the editorial title, preserving clean typography and spacing. |
| **Destination Detail** (`/explore/[slug]`) | POI / Food / Stays | Hotel images showed generic stock interiors without clear disclosure that they are illustrative category representations rather than actual property photos. | High | Visual / Honesty | Add explicit "Representative regional stay / dining" badge on non-property-verified assets to maintain 100% honesty. Verify and fix all flagship POIs for Goa, Manali, Udaipur, Jaipur, Munnar. |
| **Stories** | Stories Catalog | Story card covers used repetitive backpacker stock images. Typography was standard sans-serif with generic AI-like summary blurbs. | High | Visual / Content | Introduce editorial serif typography (`font-serif`), verified regional photography (Pir Panjal, Old Goa, Mewar, Nilgiris), and human-written dispatches. |
| **Story Detail** (`/stories/[slug]`) | Reader View | Reader view lacked cinematic header background treatment and inline visual editorial layouts (pull-quotes, asymmetrical multi-photo galleries). | Medium | Visual | Add full-bleed photo header with soft photographic gradient, rich multi-column gallery layouts, and elegant serif typography. |
| **Planner Stage 1** | Form Controls | Form inputs had heavy outlines, date picker was unstyled browser default, quick corridor chips lacked visual polish. | Medium | Visual / Interaction | Refine input fields with warm sand borders (`#EBDCC7`), subtle focus ring in Primary Teal (`#1F6E78`), and interactive corridor chips with price badges. |
| **Planner Stage 1** | Edge Cases | Entering the same origin and destination (e.g. Pune → Pune) showed an inline warning but could still allow weird states if typed rapidly; 0 budget allowed submission attempt. | High | Functional / Edge Case | Enforce rigorous client validation: same-location detection, sane budget bounds (minimum ₹5,000, maximum ₹10,00,000), positive integer travellers (1-20), and friendly guidance. |
| **Planner Stages 2–6** | Global Budget Editing | **CRITICAL DEFECT:** User could NOT edit or increase budget after Stage 1. Budget was purely static text in top nav. If transport or stays pushed cost higher, user had no way to adjust budget without restarting. | Critical | Functional / UX | Implement global planner budget control chip: `Budget ₹25,000 ✎` accessible across Stages 2, 3, 4, 5, 6. Opens accessible popover/inline input with instant recalculation. |
| **Planner Stages 2–6** | Budget Increase | Budget increase was not supported mid-flow. | Critical | Functional | Handle budget increase: update state, persist to `sessionStorage`, recompute surplus (`remainingBudget`), preserve all selected items. |
| **Planner Stages 2–6** | Budget Decrease | If user decreases budget below current expenditure, selections could be silently invalidated or cause unexpected state. | Critical | Functional / Edge Case | If budget < selected total cost, display explicit warning: "Your current selections exceed the new budget by ₹X" with actions: "Adjust selections" or "Restore previous budget". Never silently delete selections. |
| **Planner Stage 2** | Transport Stage | Route cards had plain list styling, lacking an authentic journey timeline feel. Mode icons and layovers were understated. Hover and selection lacked animation. | Critical | Visual / Interaction | Rebuild Transport Stage into a signature travel comparison timeline: clear departure/arrival nodes, vertical connecting route bar with transport icons (Train, Bus, Flight, Cab), layover badges, and subtle route line draw on selection. |
| **Planner Stage 3** | Places Stage | "Must Visit" toggle was subtle and card hover did not clearly reveal selection state. Image aspect ratios were inconsistent. | High | Visual / Interaction | Re-architect attraction cards with 16:9 ratio, clear "Add" and "Must Visit" tactile states, verified landmark imagery, and zero generic stock. |
| **Planner Stage 4** | Food Stage | Some food items used generic stock dishes that did not match the destination (e.g. continental breakfast for Goa or Manali). | High | Visual / Content | Ensure authentic regional culinary items (Goan fish curry, thali, poi, siddu, kachori) with diet badges (Veg / Non-Veg) and accurate cost estimates. |
| **Planner Stage 5** | Stay Stage | Accommodation cards lacked clear category tiering (Budget Homestay vs Boutique Heritage vs Luxury) and transparent pricing breakdowns. | High | Visual / Content | Modernize stay cards with clear tier tags, nightly vs trip total breakdown, and honest "Illustrative category property" disclosure where appropriate. |
| **Planner Stage 6** | Budget Review | Nested cards inside cards created an intimidating, cluttered dashboard feel rather than a serene final review. | High | Visual / Hierarchy | Simplify Review Stage with clean horizontal dividers, compact category rows with individual "Edit" quick links, and a prominent "Generate Itinerary" CTA. |
| **Planner Stage 7** | Itinerary Hero & Timeline | Screen looked too technical with raw algorithm metadata; day transitions lacked visual distinction; map interaction was passive. | Critical | Visual / Interaction | Elevate Itinerary to NAVIX flagship screen: authentic destination backdrop hero, editorial day tabs (Day 1, Day 2...), interactive timeline with major photos, and map marker cross-highlighting on hover/click. |
| **Interactive Map** | Map Markers & Bounds | Selecting an itinerary event did not smoothly pan the map; Leaflet popup was standard unstyled white box. | Medium | Interaction / Visual | Style Leaflet popups with custom brand styling (`#142A38` text, `#1F6E78` accents); connect timeline activity clicks to map flyTo/highlight. |
| **Dashboard** | My Trips | Looked like an empty generic table when no trips were saved; saved trip cards lacked photographic destination covers. | Medium | Visual | Add rich empty state with "Explore Destinations" CTA; render saved trips with destination hero imagery, budget breakdown, and direct re-open link. |
| **Login / Register** | Auth Forms | Dark mode remnants clashed with the warm editorial palette; form errors were generic. | Medium | Visual | Harmonize auth screens with warm editorial palette (`#FBF7F1` background, `#FFFDFC` card, `#1F6E78` primary buttons, clean typography). |
| **PDF Itinerary** | Export Document | Exported PDF could render raw JSON or broken images on complex multi-modal itineraries; currency symbol ₹ occasionally rendered as '?' on older PDF viewers. | High | Functional / Visual | Ensure clean HTML-to-PDF print styling with unicode fallback for `₹` / `INR`, clean page breaks, and embedded high-res assets. |
| **Mobile Layout** | All Screens (360-390px) | Context bar overflowed on 360px screens; transport timeline had tight horizontal padding; modal / popovers could clip off-screen. | High | Mobile / UX | Optimize mobile breakpoints: stack Trip Composer cleanly, compact horizontal scroll for stage stepper, full-width touch-friendly budget popover. |
